## 网站简介

本站是我的个人技术文档站点，用于记录本次「通过 GitHub Actions 自动部署静态文档到 GitHub Pages」实践的过程与结果。

站点共四个页面：**首页**说明站点用途，**关于**介绍项目目标与技术组成，**使用指南**给出日常操作流程与常用命令，**API 参考**以文档示例的形式展示接口描述写法。

## 实践体会

这次实践让我第一次完整走通了「源码 → 构建产物 → 部署 → 公开网站」这条链路。过去我接触的都是前后端分离的动态网站，页面由服务器在每次请求时实时生成；而 MkDocs 这类静态站点把「生成」这一步提前到了构建阶段：`mkdocs build` 在我的电脑上或 GitHub 的服务器上把 Markdown 一次性编译成 HTML/CSS/JS，之后 GitHub Pages 只需要把这些现成的文件原样发出去即可。

也正因为如此，`site/` 目录属于构建产物，不需要手工维护，更不该提交进仓库——它随时能由 `docs/` 重新生成，这一点和编译产物、依赖包目录是一样的道理。理解了这层关系，工作流里「先 build 再 deploy」两个任务的设计、以及只改 `report/` 不会触发部署，就都顺理成章了。
